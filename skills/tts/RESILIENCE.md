# Устойчивый длинный прогон

Этот маршрут применяй, когда книга проходит несколько стадий подряд: подготовка текста, EPUB, TTS, ASR и MP3. Выход из процесса или надпись `running` не доказывают ни успех, ни окончательный сбой. Истина — проверенные артефакты и журнал батчей.

## Перед стартом

1. Зафиксируй хэш исходника и создай манифест глав и батчей. На границе каждой стадии проверь количество и порядок разделов, непустые заголовки, покрытие исходного текста и отсутствие служебных заглушек. Равное число абзацев само по себе не обнаруживает их сдвиг: сравни заголовки и содержимое по позициям. Исправляй только затронутые блоки, затем пересобирай зависимые артефакты.
2. Запусти `scripts/preflight_local.py` тем же Python и с теми же переменными окружения, которые получит рабочий процесс. Проверь короткий реальный фрагмент до конца: синтез, WAV, независимый ASR, MP3 и полное декодирование.
3. Сохрани в состоянии путь и хэш входа, версию модели и библиотек, PID и команду процесса, время обновления, счётчик готовых батчей, оставшиеся проверки. Записывай JSON атомарно через `.part` и переименование.

## Передача между стадиями

- Очередь TTS ждёт **проверенный** входной EPUB/Markdown: файл существует, хэш совпадает с отчётом, архив EPUB открывается, оглавление и порядок глав проверены. Один статус `complete` в JSON не служит пропуском.
- При исправимом сбое предыдущей стадии ставь очередь в `waiting_for_repair`, сохраняя уже готовые WAV и ASR. После ремонта повторно проверь артефакт и продолжи. Не превращай разовый сбой upstream в постоянное `audio_failed` без механизма повторного запуска.
- Для действительно безнадзорной очереди нужен наблюдатель: он сверяет PID **с командой**, свежесть обновления, рост счётчика и ошибки; после заданного порога отсутствия прогресса сообщает причину и останавливает бесконечные повторы. PID без проверки может принадлежать другому процессу.
- При перезапуске сравни ключ кэша каждого батча: исходный текст, модель и квантизация, голос, параметры, хэш WAV, ASR-модель. Совпадающие завершённые батчи пропускай; неполный `.part` удаляй или пересоздавай. Старые `error` и `traceback` очищай после успешного перехода, иначе отчёт вводит в заблуждение.
- Ошибку отдельного TTS/ASR-батча записывай отдельно и продолжай независимые батчи. После первого прохода повторяй только технические сбои с ограниченным backoff; проблемный текст дели на меньшие части. Предупреждение ASR не является техническим падением и не должно прерывать синтез остальных глав.

## Особенности локального macOS/MLX

- В ограниченной среде `mlx` может сообщить `No Metal device available`; проверь тот же Python вне ограничения до установки новых моделей или исправления текста. Не стирай кэш и не выдавай отсутствие GPU за дефект WAV.
- На некоторых Homebrew Python `platform.mac_ver()` возвращает пустую строку в ограниченном запуске; `truststore` или `uv` затем ошибаются при импорте/создании venv. Проверь `platform.mac_ver()` в рабочем процессе. Если нужен `DYLD_LIBRARY_PATH` для `pyexpat`, передай его **непосредственно Python**. В одном локальном прогоне запуск через системный `caffeinate` потерял нужное окружение у дочернего Python; запускай Python отдельно, затем `caffeinate -i -w <PID>`.
- Если `uv venv --python python3.x` пытается скачать интерпретатор при недоступной сети, укажи абсолютный путь к уже установленному Python. Если `uv` всё равно отказывает из-за пустого `platform.mac_ver()`, создай окружение через `<python> -m venv --without-pip <venv>`, затем запусти `<venv>/bin/python -m ensurepip` с корректной библиотекой `expat`. Не меняй рабочее окружение другой задачи.
- Локальная папка `mlx_whisper` должна содержать `config.json` и `weights.safetensors` либо `weights.npz`. Если скачанный кэш хранит вес как `model.safetensors`, создай в рабочей папке ссылку с ожидаемым именем; не переименовывай общий кэш. Проверь модель на коротком WAV до запуска книги.
- Если пакетный менеджер не может проверить Python или сеть временно недоступна, сохрани уже установленные зависимости и аудиокэш. После проверки окружения повтори установку отдельно; не перезапускай из-за этого синтез готовых батчей.

## Разбор ошибки по её сигнатуре

| Симптом | Что проверить и как продолжить |
|---|---|
| Все пакеты текста готовы, но сборка сообщает `Heading hierarchy changed` | Выведи индекс первого несовпавшего заголовка и соседние исходные/переведённые блоки. Модель может объединить соседние абзацы, выдать пустое `### ` или заглушку при **том же числе** элементов JSON. Восстанови границы и содержание только повреждённого чанка; повтори сборку и проверку покрытия. Не запускай заново всю книгу. |
| `platform.mac_ver()` пуст или `truststore` падает с `invalid literal for int()` | Сравни среду пилота и фонового процесса. На macOS проверь, не потерял ли системный wrapper `DYLD_LIBRARY_PATH`; запусти Python напрямую, а удержание бодрствования привяжи отдельно к его PID. |
| MLX Whisper выдаёт `[load_npz] Input must be a zip file` при наличии `model.safetensors` | Локальный загрузчик искал `weights.safetensors`/`weights.npz`. Создай в рабочей папке ссылку `weights.safetensors` на имеющийся файл и повтори короткий ASR-пилот. |
| Установка необязательной библиотеки прервалась на `NameResolutionError` | Не останавливай синтез и ASR, если их зависимости уже работают. Зафиксируй неполный аудит в отчёте, повтори загрузку позднее с ограниченным backoff; не называй мастер проверенным до закрытия обязательных QC-пунктов. |
| Короткий заголовок даёт покрытие около `0.83` из-за римской цифры | Сверь сырой ASR с WAV и укажи профиль заголовка. При реальном пропуске произноси номер словами и пересинтезируй только этот батч; не снижай порог всему корпусу. |
| Батч со множеством латинских сокращений через `/` распознан как повтор «или» либо сокращения исчезли | Проверь само звучание: это может быть ошибка TTS, а не только Whisper. Подготовь произносимые фонетические замены для конкретных сокращений, сохрани карту `исходник → TTS-текст`, пересинтезируй затронутые батчи и повтори ASR. Одними алиасами QC проблему не скрывай. |

## Финальный рубеж

- Если не хватает WAV или есть технические сбои, не собирай даже ранний мастер: сначала восстанови полный набор в зафиксированном порядке.
- Если весь звук есть, но остались ASR-предупреждения или неполный аудит ударений, пользовательский ранний выпуск называй `unverified`, прикладывай снимок предупреждений и хэши. Продолжай ремонт исходных батчей; не переименовывай раннюю версию в проверенный мастер.
- Глобальное покрытие словарём ударений не заменяет порог **каждого** батча; словарь даёт кандидаты, но не разрешает омографы по контексту и не подтверждает произнесённое ударение. Короткие заголовки оценивай по своему профилю и перепроверяй ложные ASR-хвосты на WAV.
- Перед финальным именем полностью декодируй каждый MP3, проверь длительность, порядок глав, теги, размер и SHA-256. В отчёте отдельно укажи машинную редактуру перевода, автоматический QC и человеческое прослушивание.
