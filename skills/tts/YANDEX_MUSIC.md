# Подготовка и загрузка в Яндекс Музыку

## Что проверять заранее

Собственные треки загружаются через сайт или настольное приложение и предназначены для личного прослушивания. Перед загрузкой сверяй актуальную справку и ограничения интерфейса: лимиты и поддерживаемые профили могут меняться.

Не отправляй единственную локальную копию. Сохраняй мастер, а для сервиса создавай отдельные производные файлы.

## Совместимый профиль

Если исходный mono/24 kHz MP3 получает нестабильные ошибки, рабочий совместимый вариант:

```bash
ffmpeg -hide_banner -loglevel error -y \
  -i chapter.mp3 \
  -map_metadata 0 \
  -ar 44100 -ac 2 \
  -c:a libmp3lame -b:a 96k \
  -id3v2_version 3 \
  chapter-yandex.mp3
```

Это наблюдавшийся практический обход, а не доказанная причина ошибок. В одном проекте единый mono/24 kHz мастер с пониженным битрейтом в итоге тоже был принят, хотя интерфейс сначала показал ошибку.

Перед загрузкой совместимых копий:

- полностью декодируй каждую;
- проверь `title`, `artist`, `album`;
- проверь размер каждого файла;
- сохрани исходную длительность;
- не заменяй локальный мастер производной версией.

## Поведение интерфейса

- `Uploading` означает только передачу файла.
- `Processing` может длиться несколько минут для длинной главы.
- Временная строка `Error uploading the track` не всегда окончательна: после завершения всех передач обнови страницу и проверь реальный список.
- Параллельная загрузка многих крупных файлов чаще даёт нестабильные ошибки. Повторяй неудачные главы по одной.
- Не оценивай успех по исчезновению временной строки.

Успех подтверждён, только если после обновления страницы видны:

- правильные название и исполнитель;
- ожидаемая длительность;
- значок личного трека;
- активная кнопка воспроизведения.

Если единый мастер принят, это уже завершает основную выгрузку аудиокниги. Главы можно добавлять отдельно для навигации. Не удаляй дубликаты или принятые треки без явного согласия пользователя.
