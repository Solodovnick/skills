# TTS: русскоязычные аудиокниги из PDF и Markdown

Навык для AI-агента: подготовить произносимый текст, синтезировать его локально, проверить каждый фрагмент независимым распознаванием речи и собрать главы и MP3-мастер. Подходит для длинных записей, где важны числительные, словоформы, ударения и возможность продолжить работу после сбоя.

Пакет содержит инструкции, примеры настроек и helper для проверки готовых MP3. Синтез, подготовку текста и ASR-проверку агент организует по этим инструкциям в рабочем окружении; единой команды, запускающей весь конвейер, в пакете нет.

## Быстрый вход

Подключите каталог `tts` как навык в агенте с поддержкой `SKILL.md`. Точка входа — [SKILL.md](SKILL.md). Укажите источник, рабочий каталог и желаемый голос, например:

> Озвучь `input.pdf` локально через Qwen3-TTS 8-bit. Сохрани исходник, сценарий, батчи и отчёты в `work/book/`. Проверь каждый батч независимым ASR и собери главы и MP3-мастер.

Или для голоса Ксении:

> Озвучь `input.md` голосом Silero `kseniya`. Подготовь числа по контексту через num2words, проверь словоформы и ударения через RUAccent, выборочно сверь спорные места через silero-stress и добавь SSML-паузы. Перед длинным прогоном сравни короткие варианты на слух.

Сначала нужен короткий пилот на реальном тексте, затем — полный прогон с сохранением результатов каждого батча.

## Два маршрута синтеза

| | Qwen3-TTS 8-bit | Silero / Ксения |
|---|---|---|
| Модель и голос | `mlx-community/Qwen3-TTS-12Hz-1.7B-Base-8bit`, маршрут по умолчанию для Apple Silicon | Русская модель Silero с `speaker='kseniya'` |
| Ввод | Обычный русский текст, фонетические замены сложных терминов | Подготовленный текст; после пилота — проверенные `+` и SSML |
| Ударения | RuAccent используется для лексического аудита | RUAccent и выборочная независимая сверка через silero-stress |
| Подробности | [Основной workflow](SKILL.md), [QC](QUALITY_CONTROL.md) | [Числа, ударения и SSML](SILERO_KSENIYA.md) |

В проверенном маршруте Qwen3-TTS Base 8-bit знаки `U+0301` и `+` резко ухудшили речь. Поэтому результат акцентуатора не подаётся в эту модель по умолчанию. При смене модели, версии или голоса нужен новый A/B-тест. У Silero свои правила: `+` и SSML поддерживаются отдельно.

## Подготовка слов, чисел и ударений

Качество начинается с отдельного TTS-сценария: очищенного от колонтитулов, переносов и служебного шума, с линейным чтением таблиц и словарём произношений имён, терминов и аббревиатур. Исходник и сырой экспорт сохраняются отдельно. Подробности — в [SOURCE_PREPARATION.md](SOURCE_PREPARATION.md).

Для Silero используется следующий flow:

```text
Контекст чисел и дат → regex + num2words → RUAccent
→ выборочная сверка silero-stress → SSML-паузы → Silero / kseniya
→ независимый ASR → ремонт батчей → сборка
```

1. **Определить смысл числа.** `15.07` может быть датой, десятичным числом или номером раздела. Сначала фиксируются контекст и тип записи, затем `num2words` преобразует число в русские слова. Библиотека сама не выбирает смысл и нужный падеж даты; сомнительные формы требуют ручного выбора. Карта замен сохраняет исходный фрагмент и результат.
2. **Поставить ударения без изменения словоформ.** RUAccent обрабатывает копию текста; позиции `+` переносятся на соответствующие гласные подготовленного текста. После удаления маркеров слова должны точно совпадать. Имена, термины и омографы проверяются отдельно.
3. **Сверить спорные места.** silero-stress используется выборочно как независимый акцентуатор. Расхождения идут в словарь произношений или на ручную проверку. Последовательно размечать весь текст обоими акцентуаторами не следует: метки могут противоречить друг другу.
4. **Добавить паузы.** После проверки текста формируется SSML с `<speak>` и, где нужно, `<break time="500ms"/>`, `<s>` и `<p>`. XML-символы экранируются; разметка передаётся через `ssml_text`, а не обычный `text`.

До полного прогона сравниваются обычный ввод, ввод с проверенными `+` и SSML с паузами. Встроенная расстановка ударений Silero тоже участвует в сравнении. Поддержку silero-stress нужно проверить на целевой архитектуре: опубликованные требования перечисляют x86-64; при недоступности остаются RUAccent и ручная проверка спорных слов.

## Инструменты и зависимости

| Задача | Инструменты |
|---|---|
| Qwen3-TTS на Apple Silicon | `mlx-audio` и выбранная 8-bit модель |
| Silero / Ксения | Русская модель Silero TTS с голосом `kseniya` |
| Русские числительные и ударения | `num2words`, `ruaccent`; выборочно `silero-stress` |
| Независимое распознавание речи | `mlx-whisper` и `mlx-community/whisper-large-v3-turbo-8bit` для рекомендованного Apple Silicon маршрута |
| PDF → текст и визуальная сверка | MarkItDown, Poppler (`pdfinfo`, `pdftotext`, `pdftoppm`) |
| Сборка и техническая проверка | FFmpeg, FFprobe; для helper также Bash и `shasum` |

Модели и библиотеки устанавливаются в рабочем окружении отдельно. Их версии, модель, голос и настройки входят в ключ кэша батчей. [settings.example.json](settings.example.json) содержит стартовые параметры Qwen, а [pronunciation-overrides.example.json](pronunciation-overrides.example.json) — пример фонетического словаря; это шаблоны для конкретного текста, а не готовая универсальная конфигурация.

## Имеющиеся команды

Примеры ниже выполняются из каталога `skills/tts`; пути `input.pdf`, `book.mp3` и `output/` заменяются на ваши.

Для текстового PDF:

```bash
markitdown input.pdf > raw.md
pdfinfo input.pdf
pdftotext -layout input.pdf extracted.txt
pdftoppm -f 1 -l 5 -r 144 -png input.pdf page
```

`raw.md` остаётся сырым экспортом. Перед синтезом нужно сверить репрезентативные страницы и создать отдельный чистый сценарий. Для сканированного PDF нужен OCR.

Полное декодирование одного готового MP3:

```bash
ffmpeg -v error -i book.mp3 -f null -
```

Проверка всех MP3 в каталоге и его подпапках:

```bash
bash scripts/validate_audio.sh output/
```

[validate_audio.sh](scripts/validate_audio.sh) выводит параметры аудиопотока, длительность, размер и основные теги, полностью декодирует файлы и считает SHA-256. Скрипт завершится с ошибкой при отсутствии MP3 или необходимой команды. Он проверяет техническую читаемость файлов; ASR и проверка произношения выполняются на предыдущих этапах.

## Контроль качества и возобновление

Текст делится по абзацам и предложениям; стартовый ориентир — до 1200 символов на батч. Для каждого фрагмента сохраняются исходный диапазон, финальный текст, настройки, ключ кэша, WAV, хэш, ASR-транскрипт и решение QC. Повторный запуск использует готовые фрагменты с совпадающими ключом и хэшем; ремонт затрагивает только проблемные батчи.

Перед сборкой проверяются:

- сохранность словоформ после разметки и лексическое покрытие ударениями не ниже 0.98 либо явно описанное исключение;
- независимый ASR каждого батча: нормализованное покрытие слов не ниже 0.85 и WER в пределах профиля текста;
- все предупреждения, включая пропуски, повторы и ошибки окончаний; блокирующие списки ошибок должны быть пусты;
- после сборки — полное декодирование, длительность, теги и SHA-256 каждого итогового файла.

Пороги WER различаются для прозы, титульного блока, технического текста и таблиц. Нормализация не должна скрывать русские окончания. Полные правила и порядок ремонта — в [QUALITY_CONTROL.md](QUALITY_CONTROL.md).

Whisper распознаёт слова, но не выдаёт позиции ударений. RUAccent + ASR помогают проверить текст и слышимость слов; правильное ударение в аудио и интонация требуют слуховой проверки либо отдельного акустического анализа. Итоговый отчёт явно указывает, была ли человеческая слуховая редактура: `stress_and_intonation_reviewed_by_human: true/false`.
