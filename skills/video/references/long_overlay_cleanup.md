# Длинное видео: очистка по сценам и частям

Применяй этот маршрут, когда наложение держится десятки минут, меняет положение либо попадает на разные поверхности. Это не готовая маска для произвольного ролика: геометрию и границы надо заново подтвердить на его исходнике.

## Покрытие до рендера

1. Зафиксируй хэш, размер, реальные PTS, CFR/VFR, число кадров и потоки. Отдельно найди первый полезный кадр и начало концовки, только если пользователь просил их вырезать.
2. Собери разреженный контактный лист по всему таймлайну, затем плотные последовательности у смен сцен, появления рекламы и прохода тела возле неё. Порог scene detection — источник кандидатов, а не доказательство, что все монтажные переходы найдены; проверь соседние кадры, в том числе две последовательные склейки и одиночные вспышки.
3. Раздели маску для модели и маску итогового композитинга. Первая скрывает всю рекламу от inpaint, вторая возвращает синтезированные пиксели лишь в выбранную область. Для движущейся плашки определи её положение на каждом кадре и добавь bounded маску; проверь края, тени, контуры и исчезание элементов. Не расширяй её до края кадра без визуального основания.
4. Проверь короткие пилоты на гладкой стене, полу/коврике, одежде и пересечении маски с человеком. Ровную поверхность можно восстановить локальной подгонкой по открытым пикселям, но включай её только после проверки ошибки подгонки на известной области и ограничивай запись синтеза фактической высотой наложения: успешная подгонка стены сама по себе не разрешает закрашивать руку под рекламой. Коврик и пол с разной фактурой восстанавливай отдельно; не перетирай геометрическую границу одной заливкой. Небольшой фиксированный остаток на доказанно чистом фоне можно исправить локальным inpaint, не затрагивая соседнее тело.

## Временная обработка и очередь

- На длинной записи можно считать LaMa только на опорных кадрах и переносить очищенную область между ними оптическим потоком. Подбирай шаг на пилотах с движением; один удачный still не доказывает отсутствие мерцания. На каждом подтверждённом cut заканчивай интерполяцию перед склейкой и начинай новый опорный кадр после неё. Не переноси предсказание через переход.
- Делай небольшие части с границами на известных склейках. Записывай интервал исходных кадров `[start, end)`, параметры, лог, PID и ожидаемое число кадров. Частичный файл называй `.working.mp4`; после успешного выхода кодировщика и точного packet count переименовывай в завершённую часть. При возобновлении сверяй файл и процесс, а не только состояние JSON.
- Сначала собери video-only из завершённых частей с проверкой общего числа кадров. Если начало обрезано по нецелому числу аудиосэмплов или исходный AAC нужно точно сдвинуть, перекодируй звук один раз с `atrim`/`asetpts` и проверь синхронизацию с исходником. Не считай сам факт наличия аудиопотока проверкой синхронизации.

## Проверка

- На каждой части сравни неизменённую центральную область с теми же исходными кадрами, а углы просматривай на контактных листах и в движении. `scripts/check_frame_alignment.py` делает точечную проверку CFR mapping; его центр должен быть вне масок и других намеренных изменений. Для VFR используй PTS, этот скрипт для него не предназначен.
- Цветовой поиск ярких букв удобен как быстрый фильтр, но бледные контуры, пятна и неправильную фактуру он пропустит. Проверяй исходник и результат рядом на одинаковых кадрах, особенно сразу после cut; случайные кадры из длинного таймлайна дополняй плотной проверкой рискованных интервалов.
- Если эффект по ошибке затронул область вне подтверждённого наложения, верни в ней исходные пиксели при точном соответствии кадров. Проверь на исходнике, что реклама в этой области действительно отсутствует, и просмотри пересечение с движущимся телом перед заменой частей.
- После mux проверь полный decode, разрешение, FPS, число кадров, начало/конец, длительности потоков и звук. `scripts/check_audio_alignment.py` сравнивает несколько слышимых окон исходного и итогового аудио; тихое окно отмечается отдельно. Его порог сдвига 20 мс и корреляция 0,97 подходят как первичная техническая проверка, а не заменяют прослушивание рискованных стыков.

Пример для CFR, если полезный материал начинается с исходного кадра `START_FRAME`:

```bash
python scripts/check_frame_alignment.py --source "$SOURCE" --candidate "$CLEAN" \
  --source-frame-start "$START_FRAME" --expected-frames "$EXPECTED_FRAMES"
python scripts/check_audio_alignment.py --source "$SOURCE" --candidate "$CLEAN" \
  --source-start "$START_SECONDS" --duration "$DURATION_SECONDS"
ffmpeg -v error -i "$CLEAN" -f null -
```

Установи `opencv-python` и `numpy` в рабочем venv для этих двух скриптов. Их PASS означает только точное соответствие проверенных кадров и аудиоокон; визуальное качество скрытых рекламой участков оценивай отдельно.
