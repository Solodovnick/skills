# Повторное использование проверенного очищенного видео

Применяй, когда несколько записей содержат одинаковые упражнения или длинные повторяющиеся сцены, а одна версия уже очищена и прошла визуальный и технический QA. Повтор материала подтверждай по декодированным кадрам, а не по названию, похожей длительности или нескольким превью.

## Найти и доказать соответствие

1. Сними FFprobe-инвентарь каждой записи: FPS/CFR или VFR, размер кадра, число кадров, потоки и границы заставки/концовки. Для VFR строй соответствие по PTS; приведённый ниже скрипт рассчитан на CFR.
2. Сравни разреженные кадры по всему ролику. При совпадении первых кадров отдельно проверь середину и конец: запись может повторять начало, затем перейти к другому фрагменту. Найди переход покадрово, включая одиночные дубли и вспышки.
   Для первичного поиска `scripts/fingerprint_1fps.py` декодирует видео в маленький grayscale-индекс, а `scripts/match_fingerprints.py` ищет близкие секунды в уже очищенном ролике. Это лишь кандидаты: фильтр `fps=1` не даёт точной границы в кадрах, а похожий фон может совпасть при другом упражнении. Уточняй каждый непрерывный участок на исходном FPS и по PTS; различай повтор сцены, одиночный дубликат кадра и новый фрагмент.
3. Запиши монтажную карту полуоткрытыми интервалами `[start, end)` в *кадрах*: для каждого интервала исходника укажи интервал проверенного очищенного видео и ожидаемое число выходных кадров. Каждую смену смещения подтверди кадрами непосредственно до и после неё. Сохрани ссылку на исходный артефакт и его QA, но не публикуй частные видео, пути или контактные листы вместе с навыком.
4. `scripts/compare_mapped_frames.py` меряет различие кадров двух CFR-записей при заданных начальных индексах и длине интервала. Запускай его отдельно для каждой строки карты, достаточно плотно по всему интервалу и обязательно на его границах. Кодирование может давать небольшую MAE; калибруй допустимое значение на заведомо совпадающих кадрах и вручную разбирай выбросы. Численная близость не доказывает, что закрытая наложением область очищена хорошо.

### Когда разреженного поиска недостаточно

Если запись склеена из нескольких повторов с разными смещениями, сделай 32×18 grayscale-индекс **каждого** декодированного кадра через `scripts/index_all_frames.py`. Это 576 байт на кадр без потерь числа кадров. `scripts/find_dense_shift.py` ранжирует смещения около предполагаемого значения по медианной и 95-й перцентильной MAE. `scripts/scan_dense_offsets.py` находит непрерывные интервалы при выбранных смещениях и сохраняет их полуоткрытые границы. `scripts/detect_cuts_dense.py` выделяет кандидатов на монтажные переходы в неподобранных интервалах. Скрипты рассчитаны на одинаковый CFR и порядок кадров; похожий однотонный фон даёт ложные совпадения, поэтому карту подтверждай полноразмерными кадрами и соседями каждого стыка.

```bash
python scripts/index_all_frames.py --input "$SOURCE" --output source.32x18.gray
python scripts/index_all_frames.py --input "$REFERENCE" --output reference.32x18.gray
python scripts/find_dense_shift.py --query source.32x18.gray \
  --reference reference.32x18.gray --q-start 1000 --q-end 10000 \
  --shift-center 0 --shift-radius 48
python scripts/scan_dense_offsets.py --query source.32x18.gray \
  --reference reference.32x18.gray --shift 0 --shift 17 \
  --threshold 1 --min-run 24 --output dense_matches.json
python scripts/detect_cuts_dense.py --index source.32x18.gray \
  --start 1000 --end 10000 --threshold 12 --output cut_candidates.json
```

Плотные скрипты требуют NumPy и FFmpeg; `check_seams.py` ниже также требует OpenCV. Порог 1 для уже перекодированных копий может быть слишком строгим. Калибруй его на подтверждённом повторе и исключай рекламные области при окончательной проверке; низкое разрешение индекса само по себе не доказывает корректность монтажа.

```bash
python scripts/fingerprint_1fps.py --input "$SOURCE" --output source.gray
python scripts/fingerprint_1fps.py --input "$CLEAN_REFERENCE" --output clean.gray
python scripts/match_fingerprints.py --query source.gray --reference clean.gray \
  --output candidate_matches.json --step 10
python scripts/compare_mapped_frames.py \
  --left "$SOURCE" --right "$CLEAN_REFERENCE" \
  --left-start 120 --right-start 0 --frames 20000 --step 250 \
  --max-mae 10
```

## Сборка и звук

- Повторно используй только участки, для которых ранее очищенный вариант прошёл QA. Уникальные кадры обрабатывай отдельно. Одиночный дублированный кадр можно взять от проверенного соседнего кадра лишь после покадрового сравнения композиции; в ином случае очисти его отдельно. Если дубликат стоит в начале перекодируемого хвоста, фильтр `tpad` с `start_mode=clone` позволяет добавить его в тот же фрагмент без отдельного однокадрового файла. Поставь `start_duration`, равную длительности одного кадра (для 24 fps — `0.041666667`), затем проверь точное число и содержимое первых двух кадров.
- Проверяй нарезку по **декодированным кадрам**. При `-ss` и `-c copy` внутри GOP контейнер может сохранить preroll-пакеты: `nb_read_packets` отличается от `nb_read_frames`, а самостоятельный клип выглядит верно, но при concat даёт неверный стык или `Non-monotonous DTS`. Если это происходит, перекодируй проблемный фрагмент с точного кадра и новой ключевой точкой, затем снова проверь стык. На практике stream-copy concat давал неверные кадры у стыков даже после проверки числа кадров каждой отдельной части. Если дефект повторяется, собери все части через `concat` **filter** с `setpts=PTS-STARTPTS` на каждом видеовходе, одним итоговым encode и `setpts=N/(FPS*TB)` на выходе. Измерь FPS источника, не подставляй 24 автоматически.
- После concat сверь ожидаемое число кадров, кадры перед и после **каждого** стыка, последний кадр и полный decode. Нормальная длительность или packet count по отдельности не доказывают правильного порядка кадров. Следи за свободным диском до создания временных фрагментов и полного выходного файла. При нехватке места проверенные части можно передать concat demuxer и добавить исходный звук в одном FFmpeg-проходе, без отдельной полной video-only копии; затем проверяй уже итоговый файл.
- Когда после среза заставки исходный порядок всех оставшихся кадров сохранён, `scripts/check_seams.py` проверяет неизменённую центральную область вокруг перечисленных стыков. Передай индексы первых кадров новых частей через повторяемый `--seam`, исходный старт и ожидаемое число кадров. Его численный PASS дополняй просмотром наложенных областей и кадра до/после стыка; если внутри материала удалены кадры, простое постоянное смещение `--source-start` не подходит.
- Для проверки стыка извлекай кадры по точному порядковому номеру или PTS из готового файла. При GOP, B-кадрах и concat быстрый seek (`-ss` перед `-i`) может показывать соседний кадр и создавать ложный вывод о потерянной склейке. Сверяй `best_effort_timestamp` либо используй точный decode вокруг PTS. Особо проверь короткую чёрную вставку и два соседних кадра по обе стороны, если они есть в карте.
- Для итогового звука используй исходник именно данного урока. Обрежь начало на исходном таймкоде первого сохранённого кадра, точно ограничь длительность выходного видео и проверь слышимые окна в начале, середине и конце через `scripts/check_audio_alignment.py`. Если в видео намеренно вырезаны интервалы внутри, составь для звука отдельную карту соответствия и проверь каждый аудиостык.
- Финальный QA: FPS, разрешение, точное число декодированных кадров, длительности потоков, полный decode, синхронизация звука, визуальный просмотр очищенных областей и движения у стыков. Отмечай готовность только после этих проверок.
